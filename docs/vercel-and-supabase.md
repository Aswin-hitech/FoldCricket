# Supabase Bucket IP Logging & Vercel Deployment Guide

This guide explains how to set up the **Supabase Storage Bucket** for logging IP and visit details, and how to deploy the application to **Vercel**.

---

## 1. Setting up Supabase Bucket for IP Logging

The app logs visitor IP addresses, geolocation (country, city, region from Vercel headers), timestamps, and session metadata into JSON files in a Supabase Storage bucket under:
```
records/YYYY-MM-DD/<cleaned_ip>_<timestamp_ms>_<action>.json
```

### Steps:
1. Log into your [Supabase Dashboard](https://supabase.com/dashboard).
2. Go to **Storage** in the left sidebar and click **New bucket**:
   - **Bucket name**: `ip-logs` (or any custom name)
   - **Public bucket**: Can be private (the service role key or anon key with storage upload policy will write to it)
   - Click **Save**.
3. Go to **Project Settings** ➔ **API**:
   - Copy your **Project URL** (`https://xyzcompany.supabase.co`)
   - Copy your **anon public key** or **service_role secret key** (recommended for private storage writes).

## 2. Supabase First-Game Feedback Collection

When new players finish their first match of FoldCricket, an interactive feedback modal invites them to share their rating (1-5 stars), selected category tags, and thoughts/vintage school memories.

The feedback is saved asynchronously to:
1. **Supabase Storage Bucket**:
   ```
   feedback/YYYY-MM-DD/<player_id>_<timestamp_ms>.json
   ```
2. **Optional Supabase SQL Database Table (`feedback`)**:
   Run this SQL in your Supabase SQL Editor if you wish to query reports via SQL or dashboard table view:
   ```sql
   create table if not exists public.feedback (
     id bigint generated by default as identity primary key,
     created_at timestamp with time zone default timezone('utc'::text, now()) not null,
     player_id text,
     player_name text,
     rating integer check (rating >= 1 and rating <= 5),
     feedback_text text,
     categories text[],
     room_code text,
     ip text,
     metadata jsonb default '{}'::jsonb
   );

   -- Allow insert by anon/service key
   alter table public.feedback enable row level security;
   create policy "Allow inserts for feedback" on public.feedback for insert with check (true);
   ```

## 2.1 Player Accounts in Neon Postgres

Player accounts are created and stored by the backend only; the browser keeps
just an opaque bearer token. Passwords are hashed with Werkzeug (scrypt) and
session tokens are stored only as SHA-256 hashes. Supabase is still used for
IP/feedback Storage logs, but account rows live in Neon.

1. In the [Neon dashboard](https://console.neon.tech) copy the **pooled**
   connection string (it already contains `sslmode=require`).
2. Set `DATABASE_URL` in the backend environment. Leave `USER_STORE=auto`
   (the default). The backend creates the account tables on first boot, so no
   manual SQL step is required.
   Optional: run
   [`backend/neon/accounts_schema.sql`](../backend/neon/accounts_schema.sql)
   once in the Neon SQL Editor if you also want the full user-data schema
   (friendships, match stats, achievements, DMs, play invites).
3. Restart the backend and check `GET /health`. `"account_store": "postgres"`
   confirms the durable store is active.

In `auto` mode the backend probes the two account tables at boot, creates them
when they are missing, and stays on SQLite only when `DATABASE_URL` is absent or
the database is unreachable, so sign-in never breaks. Postgres is authoritative;
the local SQLite file is kept as a mirror so friend lists and user search keep
working, and both stores are reconciled on every boot. Existing local accounts
are pushed to Neon on the first boot.

## 3. Deploying the Frontend to Vercel

The frontend is a React + Vite SPA with built-in Vercel serverless functions (`api/log-ip.js`) and SPA rewrite routing (`vercel.json`).

### Step-by-Step Vercel Deployment:
1. Push your repository to **GitHub** / **GitLab** / **Bitbucket**.
2. Open your [Vercel Dashboard](https://vercel.com/new) and click **Add New Project** ➔ **Import Git Repository**.
3. In **Build and Output Settings**:
   - **Framework Preset**: Vite
   - **Build Command**: `cd frontend && npm install && npm run build` (or `npm run build` if Root Directory is set to `frontend`)
   - **Output Directory**: `frontend/dist` (or `dist` if Root Directory is `frontend`)
4. In **Environment Variables**, add:
   | Variable | Value | Description |
   |---|---|---|
   | `VITE_BACKEND_URL` | `https://your-backend-app.onrender.com` | URL of your Python Socket.IO backend |
   | `SUPABASE_URL` | `https://your-id.supabase.co` | Supabase Project URL |
   | `SUPABASE_KEY` | `your-service-role-or-anon-key` | Supabase API Key |
   | `SUPABASE_BUCKET_NAME` | `ip-logs` | Supabase Storage bucket name |
5. Click **Deploy**. Vercel will build and serve your app globally with automatic HTTPS.

## 3. Hosting the Backend (Python Socket.IO)

Because HandCricket Live relies on stateful real-time Socket.IO connections (15s delivery timer, 120s disconnect grace period), the backend should be hosted on a persistent server platform such as **Render**, **Railway**, **Fly.io**, or any VPS / container host.

### Example: Deploying Backend to Render (Free/Starter):
1. In [Render](https://dashboard.render.com), click **New Web Service**.
2. Connect your Git repository.
3. Configure settings:
   - **Root Directory**: `backend`
   - **Environment**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn --worker-class gthread --threads 100 --workers 1 --timeout 120 --bind 0.0.0.0:$PORT run:app` (or `python run.py`)
4. Add Environment Variables:
   - `DATABASE_URL`: your Neon pooled connection string (`postgresql://...?sslmode=require`)
   - `CORS_ORIGINS`: `https://your-app.vercel.app`
   - `SUPABASE_URL`: `https://your-id.supabase.co`
   - `SUPABASE_SECRET_KEY`: `your-supabase-secret-key` (Storage logs only)
   - `SUPABASE_BUCKET_NAME`: `ip-logs`
   - `USER_STORE`: `auto` (Postgres when Neon is reachable, SQLite otherwise)
5. Copy your Render web service URL (e.g. `https://handcricket-live-api.onrender.com`) and paste it as `VITE_BACKEND_URL` in your Vercel project settings!

## 4. Light Mode & Dark Mode

- **Light Mode** is the **default**.
- Users can switch between Light and Dark mode using the **Sun / Moon toggle button** available in the navigation bar on all pages.
- The user's selection is stored in `localStorage` under `hcl_theme` and persists across sessions.
